# 后台体验统一化改版优先级建议

## 1. 目标

本文档用于定义后台管理系统体验统一化的首批改版优先级，确保后续实现按“高频优先、模板优先、风险可控”的原则推进。

## 2. 首批改版顺序

### 1. Users

改版目标：统一为标准“管理列表页 + 弹窗表单页”模板，作为后台高频基础页示范。

优先原因：

- 访问频率高
- 结构相对稳定
- 能验证列表页、批量操作、弹窗表单规范是否可执行

### 2. Categories

改版目标：统一树表混合视图、模板配置分组和高风险操作层级。

优先原因：

- 信息密度高，最能暴露规范是否足够清晰
- 栏目管理是后台核心建站入口之一

### 3. Sites

改版目标：统一平台管理员站点列表和站点管理员单站点配置体验。

优先原因：

- 站点页承担后台入口作用
- 与 `site_admin` 产品闭环高度相关

### 4. PublishCenter

改版目标：统一工作台信息密度、告警层级和详情追踪结构。

优先原因：

- 页面价值高但复杂度也高
- 适合作为“工作台模板”的标准验证页

### 5. SearchOps

改版目标：统一轻量工作台页和运营诊断页结构。

优先原因：

- 可作为发布中心之后的第二个工作台模板验证对象
- 页面复杂度适中，适合快速收口风格

## 3. 实施分期建议

### 一期

- `Users`
- `Categories`

目标：验证“列表页模板 + 弹窗模板”是否可稳定复用。

### 二期

- `Sites`
- `PublishCenter`

目标：验证“配置页模板 + 工作台模板”。

### 三期

- `SearchOps`
- 其余后台页面（模板、专题、导航、媒体等）

目标：将规范推广到全后台。

## 4. 验收要求

首批改版页面必须回答以下问题：

- 标题层级是否统一
- 搜索/筛选/批量操作位置是否统一
- 按钮体系是否统一
- 表格样式与状态标签是否统一
- 弹窗结构与表单校验是否统一
- 工作台类页面的信息层级是否统一

若首批页面无法满足以上问题，则视为规范仍不够清晰，需要先回补规范，再继续改版。
