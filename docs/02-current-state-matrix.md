# GovCMS 现状对照矩阵

## 1. 当前代码概览

当前仓库已经具备以下可运行代码：

- 后端控制器：认证、仪表盘、用户、角色、权限、菜单、内容、站点、栏目、模板、导航、专题、发布、媒体、门户搜索、审计日志

这说明当前仓库已经从“后台原型”推进到“后台标准版核心能力 + 门户标准版首批能力 + 搜索 / 审计增强能力”的阶段，但距离正式交付仍有明显差距。

## 3. 技术现状与目标差距

### 当前技术现状

- 后端：`Spring Boot 3.2 + Spring Security + Spring Data JPA + JWT`
- 前端：`Vue 3 + TypeScript + Vite + Ant Design Vue`
- 数据库：`MySQL 8`
- 部署形态：本地 `spring-boot:run` 与前端 `npm run dev`
- 文件存储：本地文件系统 `./storage/media` 与 `./storage/publish`
- 搜索实现：数据库表索引

### 正式目标技术口径

- 数据库目标：`KingbaseES`
- 应用服务器目标：`TongWeb`
- Web 层目标：`Nginx`
- 运行环境目标：国产 OS / 政务云兼容
- 安全目标：国密传输、国密签名、国密数据保护、审计与回滚能力

## 4. 当前代码可直接复用部分

- 认证与权限框架
- 后台前端工程基础设施
- 用户、角色、权限、菜单管理能力
- 站点、栏目、模板、导航、专题、媒体的基础数据结构与页面骨架
- 内容生命周期与审核 / 发布 / 回滚最小链路
- `RenderContextAssembler` / `PortalRenderService` 提供的受控渲染基础
- 发布任务、产物、回滚记录、轻量审计记录基础实现
- 门户搜索与数据库索引首批实现

## 5. 当前代码必须升级或继续增强部分

- 发布链路需要从“同步执行增强版”升级到“生产级发布编排”
- 审计能力需要从“轻量留痕”升级到“完整审计中心 / 运维视图”
- 搜索能力仍需从“增强可用”继续升级到“搜索建议 + 更复杂相关度 + 更完整运营分析”
- 安全能力需要从普通 JWT 升级到满足国密要求的正式方案
- 部署能力需要从本地开发口径升级为正式信创部署口径

## 6. 当前阶段结论

当前项目已经形成“后台标准版首批闭环 + 门户标准版首批闭环 + 搜索 / 审计首批能力”。接下来的重点应在两条主线中做取舍：

- 若继续扩产品能力，优先增强搜索与搜索索引体验
- 若转向正式交付，优先推进信创 / 国密 / 部署交付闭环
