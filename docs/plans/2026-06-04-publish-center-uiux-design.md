# 发布中心 UI/UX 重新设计

> 视觉方向：Industrial Command Center（工业控制中心）  
> 核心隐喻：内容发布是一条 CI/CD 流水线，任务在其中一步步推进，状态必须一目了然。

---

## 目标

让发布中心从"表单 + 表格 + 弹窗"的通用 admin 模板，变成一个**状态可见、操作有确认、反馈即时**的任务控制中心。

## 设计原则

1. **状态优先**：任务状态是最需要第一眼看到的信息，用颜色和动效强化。
2. **流程可见**：通过状态机可视化条，让用户立即理解任务当前所处阶段。
3. **操作有确认**：重试、回滚、审批等不可逆/高影响操作必须有二次确认。
4. **反馈即时**：校验结果、影响范围、执行结果都在操作点附近出现，减少页面跳转。

## 视觉系统

### 状态色（发布中心专属）

| 状态 | CSS 变量 | 色值 | 用途 |
|---|---|---|---|
| created / queued | `--status-pending` | `#94a3b8` | 等待中 |
| staging_rendering / production_rendering | `--status-rendering` | `#3b82f6` | 渲染中（脉冲动画） |
| staging_ready | `--status-ready` | `#f59e0b` | 待审批 |
| approved | `--status-approved` | `#06b6d4` | 已批准 |
| published / success | `--status-published` | `#10b981` | 已发布 |
| failed / rollback_failed | `--status-failed` | `#ef4444` | 失败 |
| rejected | `--status-rejected` | `#b91c1c` | 已拒绝 |
| rolled_back / rollback_success | `--status-rolled-back` | `#8b5cf6` | 已回滚 |

### 表面与层级

- 顶层统计卡：白色背景 + 细边框 + 微阴影
- 发布入口卡：白色背景，左侧主操作区
- 摘要卡：浅灰背景 `#f8fafc`，与入口形成层次
- 流水线列表：白色行 + hover 高亮 + 左侧 3px 状态条
- 日志终端：深色 `#0f172a` + 等宽字体 + 彩色文字

### 动效

- **状态脉冲**：渲染中状态的指示灯 1.5s infinite pulse
- **结果面板滑入**：校验/影响结果从右侧淡入 250ms
- **hover 操作显现**：任务行 hover 时右侧操作按钮从 opacity 0 到 1，200ms
- **Modal 内容切换**：标签页切换时内容 fade 150ms

## 页面布局

### 1. 顶部状态概览（Hero Stats）

一行 4 张统计卡：

```
[ 待处理  ] [ 今日成功 ] [ 失败/需关注 ] [ 最近发布 ]
```

- 数据来自 `jobs` 数组的客户端计算，不新增 API 调用。
- 点击"待处理"和"失败"卡片可快速过滤对应状态。

### 2. 发布操作面板 + 实时摘要

两栏布局：

```
[ 发布入口           ] [ 实时摘要              ]
[ 站点/单位/模式/对象 ] [ 可发布/不可发布 状态牌 ]
[ 备注               ] [ 影响项数量            ]
[ 校验/影响/执行 按钮 ] [ 原因/告警列表         ]
```

- 点击"发布前校验"后右侧显示校验结果。
- 点击"影响范围计算"后右侧显示影响项列表。
- 结果面板保留，切换发布对象时清空。

### 3. 发布流水线（历史任务）

垂直列表替代表格，每行结构：

```
┌────────────────────────────────────────────────────────────────────┐
│ ■  #142   内容 · 增量   《关于XX的通知》   张三   2小时前   [详情] │
│     staging_ready                                    [通过] [拒绝]  │
└────────────────────────────────────────────────────────────────────┘
```

- 左侧 3px 竖条表示状态色。
- 状态灯为 8px 圆点；渲染中状态带脉冲动画。
- hover 时背景变为 `#f8fafc`，右侧操作按钮显现。
- 行可点击，点击后右侧任务摘要面板更新。
- 空状态用 `.admin-empty-box` + SVG + "暂无发布任务，快去创建一条吧"。

### 4. 任务摘要侧边栏

选中任务后右侧显示：

```
任务摘要
#142 · 内容 · 增量
状态：[待审批]
操作者：张三
时间：2026-06-04 14:32
摘要：- / 失败原因

[查看详情] [通过] [拒绝]  （根据状态动态）
```

- 未选中时显示引导文案："选择左侧任务查看摘要与快捷操作"。
- 操作按钮根据状态动态显示，避免无效操作。

### 5. 任务详情弹窗

`a-modal` 宽 1000px，顶部是**状态机可视化条**，下面是 `a-tabs`：

```
created → queued → staging_rendering → staging_ready → approved → production_rendering → published
                                  ▲
                               当前状态高亮

[ 概览 ] [ 影响项 ] [ 产物 ] [ 日志 ] [ 审计 ] [ 回滚 ]
```

#### 状态机可视化条

- 水平步骤条，每步一个圆点 + 下方标签。
- 当前状态圆点放大 + 发光阴影。
- 已完成步骤用实线连接，未开始用虚线/灰色。
- failed / rejected / rolled_back 作为异常终止态，高亮显示并跳过后续步骤。

#### 标签页内容

- **概览**：任务 ID、对象、模式、状态、操作者、时间、失败原因、操作按钮。
- **影响项**：影响页面列表，带 pageType / action / path。
- **产物**：artifact 列表，含 outputPath / version。
- **日志**：Terminal 风格代码块，保留深色背景和等宽字体。
- **审计**：审计记录时间线。
- **回滚**：回滚关系表，空状态友好提示。

## 交互细节

### 发布执行

1. 用户填写表单，点击"创建并执行发布"。
2. 按钮进入 loading 状态。
3. 成功后 `message.success('发布任务 #142 已创建')`。
4. **不自动打开详情弹窗**——用户手动点"详情"。
5. 历史任务列表自动刷新。

### 回滚操作

1. 用户在列表或摘要面板点击"回滚"。
2. 弹出 `Modal.confirm`，带输入框要求填写回滚原因。
3. 输入为空时禁止确认。
4. 回滚成功后刷新列表和摘要。

### 重试操作

1. 失败任务显示"重试"按钮。
2. 点击后 `Modal.confirm` 确认："确定重试任务 #142？"
3. 重试成功后刷新列表，新任务出现在顶部。

## PublishTasks.vue 处理

PublishTasks 是独立的"发布任务审批"页面，当前过于简陋。重新设计后：

- 复用 PublishCenter 的任务行组件样式和状态色。
- 顶部加状态筛选（默认选中"待审批"）和刷新按钮。
- 列表只显示需要人工关注的任务（`staging_ready`、`failed`、`rejected`）。
- 审批操作更突出："批准"用绿色主按钮，"拒绝"用红色边框按钮。
- 空状态："当前没有待审批的发布任务"。

## 技术约束

- 不引入新依赖，全部基于 Vue 3 + Ant Design Vue 4 + 现有 admin-refresh.css。
- 不改动后端 API，只使用现有 `/api/publish/**` 接口。
- 类型安全：所有新增计算属性和方法都加 TypeScript 类型。
- 文件大小控制：PublishCenter.vue 目标控制在 650 行以内，过长的 scoped style 抽到 `admin-refresh.css` 或新 CSS module。
