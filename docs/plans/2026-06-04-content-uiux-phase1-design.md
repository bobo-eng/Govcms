# 内容管理模块 UI/UX 优化（第一阶段）设计文档

## 目标
在不改动后端 API 与数据库的前提下，提升内容管理（Content）与审核工作区（Review）的可读性、操作效率和流程连贯性，为第二阶段的编辑器升级打好基础。

## 范围

### 覆盖页面
- `frontend/src/views/Content.vue` — 内容列表、新建/编辑弹窗、发布检查、生命周期历史
- `frontend/src/views/Review.vue` — 待审核列表、审核详情、驳回弹窗

### 不覆盖（第二阶段或后续）
- 富文本编辑器替换
- 版本对比与自动保存
- 批量操作（需要后端支持）
- 新增路由或后端接口

## 视觉与信息层级

### 状态标签
- 统一使用 `docs/18-admin-ux-visual-and-interaction-guidelines.md` 的语义色：
  - 草稿：`neutral`（灰底深字）
  - 待审核：`warning`（浅黄底深字）
  - 已驳回：`error`（浅红底深字）
  - 待发布：`info`（浅蓝底深字）
  - 已发布：`success`（浅绿底深字）
  - 已下线：`neutral`（灰底深字）
- 去除高饱和纯色块，使用轻量圆角 pill 形态。

### 表格体验
- 加载态：6 行骨架屏（使用 Ant Design Vue `a-skeleton` 或项目既有骨架样式），替代当前 "加载中..." 文字行。
- 空状态：图标 + 说明文案 + 当用户有创建权限时显示 "新建内容" 按钮。
- 标题列：超长标题 hover 显示 `a-tooltip` 完整文本。
- 操作列：按规范排序为 编辑 → 次级操作 → 危险操作，统一使用文本按钮，不用纯图标。

### 弹窗规范
- 底部按钮顺序：左侧为 关闭/取消，右侧为主操作（保存、确认驳回等）。
- 危险操作使用 `Modal.confirm` 并说明后果，不只写 "是否确认"。

## 交互效率

### Content.vue
- 删除内容：`window.confirm` 替换为 `Modal.confirm`，文案说明删除后不可恢复。
- 筛选区：新增 "清空筛选" 按钮，一键重置 keyword、站点、栏目、状态。
- 分页：新增每页条数选择器（10 / 20 / 50）。
- 搜索框：300ms 防抖，减少无效请求。
- 按钮加载：保存、删除按钮增加 `loading` 状态，防止重复提交。

### Review.vue
- 审核通过：增加 `Modal.confirm`，文案为 "确认通过《标题》？通过后内容将进入待发布状态。"
- 驳回弹窗：确认驳回按钮增加 `loading`。
- 错误恢复：所有请求失败后自动关闭 loading，不锁死界面。

## 流程闭环

### 状态驱动的行内主操作
`Content.vue` 表格每行根据当前状态展示最合理的下一步操作：
- 草稿 / 已驳回 → 编辑、提交审核
- 待发布 → 去发布中心
- 已发布 → 下线
- 其他状态 → 详情

### 顶部状态统计卡
在 `Content.vue` 页面标题下方增加一排轻量统计：
- 草稿 / 待审核 / 已驳回 / 待发布 / 已发布
- 点击任一统计卡，自动将状态筛选设为对应值并刷新列表。
- 数据使用当前列表前端聚合（不新增接口），每次 `loadArticles` 后更新。

### 审核后的自动推进
- 审核通过 / 驳回成功后：关闭弹窗、显示 `message.success`、自动刷新列表。
- 若刷新后列表为空，空状态提示 "当前没有待审核内容"。

## 技术约束
- 仅修改前端 Vue 文件，**不改动后端 Java 代码**。
- **不新增 npm 依赖**。
- 继续使用 Ant Design Vue 4 现有组件：`Modal`、`Tag`、`Skeleton`、`Tooltip`、`Button`、`Select`、`Input`。
- 保持现有 `admin-refresh.css` 视觉体系，局部补充通用 utility 类即可。

## 验收标准
- `npx vue-tsc --noEmit` 通过。
- `npm run build` 通过。
- 内容列表加载时显示骨架屏，空状态含 CTA。
- 删除、审核通过均有 `Modal.confirm`。
- 状态筛选与顶部统计卡联动正确。
- 行内操作按钮根据文章状态动态显示且点击后跳转/操作正确。
